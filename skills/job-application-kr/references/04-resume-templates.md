# 이력서·경력기술서·포트폴리오

## 원칙
- **회사 지정 양식 우선.** 공채·공공기관은 대부분 채용 사이트 입력폼이다. 이때 이 템플릿은 "입력할 내용 정리본"으로 쓰고, 칸별로 복사할 수 있게 만든다.
- **자유양식이면** Markdown으로 쓰고, 제출용은 PDF로 변환한다(DOCX 요구 시 DOCX). 파일명은 `이름_회사_직무_이력서.pdf`.
- 신입 1페이지, 경력 2페이지 안팎. 경력기술서는 별도 파일로 2~4페이지.
- 최신순. 날짜 형식은 `YYYY.MM`으로 통일.
- ATS(채용관리시스템)는 텍스트를 읽는다. 표 안에 핵심 정보를 숨기지 말고, 이미지로 된 글자는 쓰지 않는다. 연락처는 텍스트로 쓴다.

## 개인정보: 넣을 것과 뺄 것
| 항목 | 기본 | 비고 |
|------|------|------|
| 이름, 연락처, 이메일 | 넣음 | |
| 사진 | **빼는 것이 기본** | 회사가 요구할 때만. 블라인드 채용이면 절대 금지 |
| 생년월일, 나이 | 뺌 | 요구 시만 |
| 주소 | 시/구까지만 | |
| 병역 | 남성은 넣음(군필/면제) | 블라인드 전형은 양식 지시에 따름 |
| 가족관계, 혼인, 신체정보, 출신지 | **넣지 않음** | 채용절차법상 요구 금지 항목 |
| 학교명 | 넣음 | 블라인드 채용이면 뺌 |
| 학점 | 3.5/4.5 이상이면 넣음 | 공채 양식은 필수인 경우 많음 |

## 이력서 템플릿 (자유양식, 경력 3년 미만 기준)

```markdown
# 홍길동
백엔드 개발자 · 010-0000-0000 · name@example.com · github.com/example · 서울 마포구

## 한 줄 소개
결제 도메인 Spring 백엔드 2년, 장애 대응 자동화로 월 롤백 4회→0회를 만든 개발자입니다.

## 핵심 역량
- **백엔드:** Java 17, Spring Boot, JPA, MySQL, Redis
- **인프라/운영:** AWS(EC2, RDS), Docker, GitHub Actions, Grafana
- **협업:** Jira, Confluence, 코드리뷰 주도 (주 10건)

## 경력
### 예시페이 · 결제개발팀 · 사원 (2024.03 - 현재, 정규직)
- 정산 배치 리팩터링으로 처리 시간 2시간 → 25분 단축
- 결제 장애 알림 체계 구축, 평균 탐지 시간 30분 → 3분
- 신규 입사자 온보딩 문서 작성, 적응 기간 2주 단축(팀 설문 기준)

## 프로젝트
### 사내 정산 대시보드 (2025.01 - 2025.04, 3명 중 백엔드 담당)
- 문제: 정산 문의 월 120건 수작업 대응
- 한 일: 조회 API 설계·구현, 권한 처리
- 결과: 문의 월 40건으로 감소

## 학력
- 예시대학교 컴퓨터공학과 학사 (2018.03 - 2024.02) · 학점 3.8/4.5

## 자격·어학
- 정보처리기사 (2023.11) · TOEIC 850 (2025.03)

## 교육·수상
- 예시 해커톤 우수상 (2023)

## 병역
- 육군 병장 만기전역 (2019.03 - 2020.09)
```

## 경력기술서 템플릿 (경력직 필수)

프로젝트 단위로, 각 프로젝트는 아래 구조. 핵심 프로젝트 3~5개만. 오래된 것은 한 줄 요약.

```markdown
# 경력기술서 · 홍길동

## 경력 요약
- 총 경력 4년 2개월 (예시페이 2년 7개월, 예시커머스 1년 7개월)
- 결제·정산 도메인 백엔드, 대용량 배치와 장애 대응 자동화 전문

## 예시페이 (2024.03 - 현재) · 결제개발팀 · 백엔드 개발

### 1) 정산 배치 리팩터링 (2025.05 - 2025.09)
- **배경:** 일 300만 건 정산 배치가 2시간 걸려 오전 업무 지연
- **역할:** 설계 및 구현 리드 (팀 4명 중 리드)
- **수행:** 청크 단위 병렬 처리, 쿼리 인덱스 재설계, 재시도 로직 분리
- **성과:** 처리 시간 2시간 → 25분, 실패 재처리 수작업 0건
- **기술:** Spring Batch, MySQL, Redis
```

## 포트폴리오 (디자인·기획·개발)
- PDF 15~25쪽 또는 노션/웹 링크. 링크는 로그인 없이 열리는지 확인.
- 프로젝트마다: 문제 → 내 역할(기여도 %) → 과정(의사결정 근거) → 결과(수치) → 회고.
- 팀 결과물은 내 담당 부분을 표시한다.
- 회사 기밀이 포함된 결과물은 공개 범위만, 필요하면 수치 마스킹.

## 맞춤 작성 절차
1. 공고의 자격요건·우대사항·주요업무에서 키워드 10~15개 추출
2. 프로필에서 각 키워드를 뒷받침하는 사실 매핑. 근거 없으면 "미충족"으로 표시하고 넣지 않음
3. 한 줄 소개를 이 직무용으로 새로 씀
4. 경력·프로젝트 순서와 불릿 강조점을 공고 기준으로 재배열
5. 공고 용어와 내 용어가 다르면, 사실 범위 안에서 공고 용어로 맞춤 (예: "데이터 파이프라인" ↔ "ETL")
6. 키워드 커버리지 표를 사용자에게 보여줌: 충족 / 유사표현 / 미충족
