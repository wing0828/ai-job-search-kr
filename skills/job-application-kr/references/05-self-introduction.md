# 자기소개서 작성 가이드

## 시작 전에 확인
1. **문항 원문**을 그대로 받는다. 문항의 동사("서술하시오", "구체적으로", "본인의 역할 중심으로")가 채점 기준이다.
2. **글자수 기준**: 공백 포함인지 제외인지. 명시가 없으면 **공백 포함**으로 보수적으로 맞춘다. 일부 구형 시스템은 바이트 기준(한글 2~3바이트)이다.
3. **블라인드 여부**: 공공기관·NCS 기반 채용이면 학교명·지역·가족 정보 금지 (`02-writing-style.md`).
4. **문항 간 사례 배분**: 같은 사례를 두 문항에 쓰지 않는다. 먼저 사례 배분표를 만든다.

```
| 문항 | 쓸 사례 | 보여줄 역량 |
|------|--------|------------|
| 1. 지원동기 | 회사 결제 서비스 사용 경험 + 정산 배치 개선 | 도메인 이해 |
| 2. 직무역량 | 정산 배치 리팩터링 | 문제 해결, 성능 개선 |
| 3. 협업·갈등 | 장애 대응 프로세스 합의 | 조율 |
```

## 글자수 운용
- 제한의 **90~100%**를 채운다. 70% 미만은 성의 부족으로 읽힌다.
- 측정은 반드시 스크립트로:
  ```bash
  python scripts/charcount.py 자기소개서_1번.txt --limit 700
  ```
  Windows에서 `python`이 없으면 설치된 Python 전체 경로를 쓴다.
- 본안과 함께 축약안(제한의 약 80%)을 낸다. 축약 시 먼저 지울 문장을 표시한다.
- 포털 입력창은 줄바꿈을 1~2자로 세는 경우가 있다. 여유를 10~20자 둔다.

## 문항 유형별 구성

### 지원동기 (+ 입사 후 포부)
구성: **왜 이 산업 → 왜 이 회사 → 왜 이 직무 → 입사 후 할 일**
- 회사만의 근거 2개 이상(사업, 제품, 최근 행보, 직무 기술서의 과업). 검증된 사실만.
- "어릴 때부터 ○○ 제품을 좋아해서"는 근거가 아니다. 제품을 써 보고 발견한 점이면 근거가 된다.
- 포부는 기간별로: 입사 1년 내(공고의 주요업무를 내 역량으로 수행) → 3~5년(전문성 확장). 막연한 "회사 발전에 기여"로 끝내지 않는다.

### 직무 역량 / 직무 관련 경험
구성: **[소제목] → 결론(역량 한 줄) → 상황 → 내가 한 행동(가장 길게) → 결과(수치) → 이 역량을 직무에서 어떻게 쓸지**
- 행동이 전체의 40% 이상.
- 공고의 직무기술서(NCS면 직무기술서의 "필요 지식·기술·태도") 용어를 사실 범위 안에서 쓴다.

### 성장과정 / 가치관
- 출생, 가족 소개 금지. **현재의 일하는 방식을 만든 사건 하나**를 고른다.
- 결론은 직무 태도로 연결: "그 이후로 저는 ~하게 일합니다."

### 성격의 장단점
- 장점: 사례 1개 + 직무 연결
- 단점: 직무에 치명적이지 않은 실제 단점 + **이미 실행 중인 보완 방법과 효과**. "완벽주의라서" 같은 위장 장점 금지.

### 협업·갈등 해결
- 갈등 상대를 나쁘게 쓰지 않는다. 상대 입장을 어떻게 파악했는지가 핵심.
- 결과에 관계 회복이나 프로세스 개선을 포함.

### 실패·도전 경험
- 실패를 실패로 인정 → 원인 분석(내 책임 부분) → 바꾼 행동 → 다음 시도의 결과.

### 회사·산업 이슈 견해
- 최근 6개월 내 이슈, 출처 확인 필수. 의견 + 근거 + 내가 직무에서 할 수 있는 일.
- 정치적 논쟁 사안이면 사실과 직무 관점 위주로.

### 자유 기술 / 하고 싶은 말
- 다른 문항에서 못 보여준 역량 하나. 감사 인사나 다짐으로 채우지 않는다.

## NCS 기반 (공공기관) 특이사항
- 문항이 "직업기초능력"(의사소통, 문제해결, 대인관계, 조직이해 등)에 대응된다. 문항이 묻는 능력 이름을 확인하고 그 능력이 드러나는 행동을 쓴다.
- 경험(직업 외)과 경력(보수 받은 일)을 구분해 쓰라는 양식이 있다. 양식대로 분리한다.
- 블라인드 규정 위반 시 실격 가능. 최종 검사에서 학교명·지역명을 grep한다.

## 첨삭 요청을 받았을 때
1. 문항 의도 대비 답변 일치도
2. 두괄식, 소제목 유무
3. 상투어 목록(`02-writing-style.md`) 검출
4. 근거 없는 주장, 프로필과 다른 사실
5. 글자수 (스크립트 측정)
순서대로 지적하고, 수정안은 원문 옆에 대조로 보여준다. 사용자의 실제 경험을 바꾸지 않는다.
